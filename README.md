# spatial-canvas-web

A responsive street map and tracked-entities bottom sheet. The map uses MapLibre GL from a CDN and OpenFreeMap's keyless dark vector style. The 3D View tilts the map and extrudes buildings where height data exists.

Serve `index.html` over HTTPS, or localhost for development. GPS and BLE access require device permissions. The map and entity list start empty until a real BLE device is detected or chosen. **Scan Real BLE / RF** uses advertisement scanning when supported, or the browser's BLE device picker. Names, service UUIDs, and exposed manufacturer data drive heuristic classification; RSSI drives signal quality and range tiers when available. Browser device IDs are not broadcast MAC addresses. BLE nodes are diagram offsets around the phone's GPS position at detection, not measured device locations. Browsers cannot scan arbitrary RF or Wi-Fi signals. No build step is required.

The **All RF / Proximity Only** control hides readings below -75 dBm in Proximity Only mode. All captured signals remain available when the control returns to All RF. Unresolved signals appear in the list but are hidden on the map until the Unresolved tab is selected. The map shows only the five strongest eligible signals with persistent identifier chips. Devices sharing a GPS fix are spread around the phone using stable ID-derived angles and RSSI range estimates. The displayed bearing is a layout aid, not a measured direction to the device. The directional beam requires an absolute compass heading; tapping the location dot or 3D View requests permission where the browser requires it. BLE does not expose device elevation.

Advertisement packets are buffered and applied every 2.5 seconds. RSSI uses an exponential moving average (25% new reading, 75% previous average); marker positions and range rings hold until the average changes by more than 4 dBm or a subsequent signal arrives after the phone has moved more than 4 meters from the anchor. Marker taps toggle the inspector, and a tap on open map space dismisses it.
